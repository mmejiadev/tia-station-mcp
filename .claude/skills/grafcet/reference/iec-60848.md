# IEC 60848 GRAFCET — what a correct chart obeys

A working summary for reading, drawing and checking charts. It paraphrases the standard and the
literature on it; it does not reproduce them. When a question turns on exact wording, the standard
is the authority, and the standard is copyrighted: buy it, do not look for a copy.

## Status of the standard (checked 2026-09-24)

- **Current edition: IEC 60848:2013, edition 3.0**, published 2013-02-27. It replaced the 2002
  edition and widened the notion of variable into input, output and internal variables.
- The IEC webstore gives a **stability date of 2028**: no new edition is expected before then. There
  is no 2025 or 2026 edition; material dated 2025–2026 builds on the 2013 text.
- European adoption: EN 60848:2013. In French and Spanish teaching it is still called GRAFCET; the
  PLC-programming cousin is SFC (IEC 61131-3), which is *not* the same language.

## Vocabulary

| Term | Meaning |
|---|---|
| Step | A state of the sequential part. Active or inactive. |
| Situation | The set of steps active at one instant. |
| Transition | A possible evolution between steps. Enabled when all its preceding steps are active. |
| Transition-condition (receptivity) | Boolean expression on a transition, over input and internal variables. |
| Clearing | What happens when an enabled transition's condition is true. |
| Action | What is done to an output or internal variable while, or when, a step is active. |
| Transient evolution | Several successive transitions cleared on one single input event. |
| Connected / partial / global grafcet | One linked chart / a set of them forming one task / every partial grafcet of one controller. |

## The syntax rule

Steps and transitions **always alternate**. Two steps are never linked without a transition between
them, and two transitions never without a step. A chart that breaks this is not a GRAFCET.

## The five evolution rules

1. **Initial situation.** At start-up exactly the initial steps (double frame) are active.
2. **Clearing.** A transition is cleared when it is enabled — every preceding step active — and its
   condition is true.
3. **Evolution.** Clearing a transition deactivates all its preceding steps and activates all its
   succeeding steps, *at the same time*. Deactivation does not happen "first".
4. **Simultaneous clearing.** Transitions that can be cleared at the same moment are cleared at the
   same moment.
5. **Simultaneous activation and deactivation.** A step that would be activated and deactivated at
   once stays active.

Rules 3 and 4 are why an implementation must evaluate every transition on the *same* situation. A
PLC scan that clears transitions one network at a time violates them unless it is written to avoid
it (see `set-reset-lad.md`).

## Transition-conditions

| Written | Meaning |
|---|---|
| `a·b` (typed `a.b` or `a*b`) | AND |
| `a + b` | OR |
| `ā` (typed `/a`) | NOT |
| `↑a`, `↓a` | Rising / falling edge: true only at the instant `a` changes |
| `=1` or `1` | Always true: cleared as soon as the step is active |
| `[T > 50]` | A numeric comparison in brackets |
| `Xn` | Step n is active |
| `t1/Xn/t2` | True `t1` after step n activates, false `t2` after it deactivates. `5s/X2` = "step 2 has been active for 5 s" |

A **level** condition (plain `a`) is true for as long as the signal is; an **edge** is true once. A
level condition reused on two consecutive transitions is the classic source of transient evolution.

## Actions

- **Continuous (assignation on state):** the variable is true exactly while the step is active.
  If several steps drive one output, the output is their OR.
- **Conditional:** continuous, but only while an extra condition holds (written above the box).
- **Delayed / time-limited:** continuous actions whose condition is a time condition on the step.
- **Stored (allocation on event):** the value is written at an instant — on activation, on
  deactivation, or on an event while the step is active — and kept until written again. `MOTOR := 1`.

During a transient evolution, continuous actions of the steps merely crossed are **not** output;
stored actions on activation or deactivation **are** executed. This is the practical difference
between the two output modes.

## Structures

| Structure | Drawing | Rule |
|---|---|---|
| Sequence | Steps one under another | — |
| Cycle | A return link to an earlier step, arrow pointing up | — |
| Selection (OR divergence) | Single horizontal line, one transition per branch below it | Branch conditions must be **mutually exclusive** |
| OR convergence | Branches each end in a transition, then join on a single line | — |
| Step skip / backward skip | A selection whose branch jumps over steps / back up | Same exclusivity rule |
| Parallel activation (AND divergence) | One transition, then a **double** line, branches below | All branches start together |
| Synchronisation (AND convergence) | Branches end on a **double** line, then one transition | Cleared only when every last step of every branch is active |
| Jump | An arrow ending on the target step's name (`X30`) | Equivalent to drawing the link |
| Source / pit transition | A transition with no preceding / succeeding step | Avoid inside hierarchies |

## Hierarchy (recognised, not generated by this skill)

- **Forcing orders** from a superior partial grafcet: `G1{}` all steps off, `G1{4}` only step 4,
  `G1{*}` frozen, `G1{INIT}` back to the initial situation. They take priority over the evolution
  rules of the forced grafcet.
- **Enclosing step** (marked `*`): while active, its enclosed partial grafcet runs; when it
  deactivates, everything enclosed stops.
- **Macro-step** `M`: replaced by an expansion that starts at `E` and ends at `S`.

A chart that uses any of these is described, never silently flattened into a sequence.

## Where the standard is ambiguous, and the reading this skill takes

The standard is semi-formal; the literature records where interpretations diverge. The positions
below follow Mroß et al. (2023) and González-Rodríguez et al. (2025):

- Every transition is evaluated on **a copy of the situation**, then all clearings are applied — the
  only reading consistent with rules 3 and 4.
- An **input edge** is true only in the first evolution it triggers, not through the whole
  transient run.
- Rule 5 means an already active step is **not re-activated**: its actions on activation do not run
  again.
- **Forcing and enclosures are pre-emptive**: a superior grafcet's order applies before the inferior
  one evolves.
- A **repeated level condition on consecutive transitions** causes transient evolution; with a level
  signal it cannot be avoided, with an edge it can.
- A PLC scan is not zero-time: an event shorter than a scan can be missed. The skill assumes the
  scan is fast compared with the process, and says so when that assumption matters.
