# Enterprise readiness

What a professional, company-grade TIA Portal engineering assistant needs, what this repository
already meets, and what it does not. Written 2026-10-13 at the user's request; it is updated with
`docs/STATUS.md` at the end of every session.

## How to read this

- **Met** means built, tested, and run at least once against the real thing. Built but never run
  against TIA Portal or a CPU is **partial**, never met — the rule this repository learned the hard
  way (see "Code never executed" in the project notes).
- Percentages are estimates of the work, not of the code: a capability that exists but was never
  measured counts for less than half.
- Standards are named so they can be looked up. Nothing here claims compliance with any of them.
  Whether a standard applies to a given customer is a question for that customer, and for some of
  them (product law, functional safety) for a lawyer or an assessor.

## The one boundary that does not move

This is an engineering tool. It is **not** a safety function and must never be presented as one.
IEC 61508, IEC 62061 and ISO 13849 require qualified tool chains and assessed processes that it
does not have. The safety function belongs to the safety controller, the robot controller and the
emergency stop. Workshop Mode stays compiled out until the conditions in `ROADMAP.md`, phase 11,
are met with a supervisor present.

## 8. Product law, for the day it is sold

Named so they are not forgotten; none of this is legal advice.

- **EU Cyber Resilience Act**: software sold in the EU with digital elements gets security
  obligations (vulnerability handling, updates, an SBOM). Check whether and when it applies.
- **Siemens Openness terms**: what a third-party product built on Openness may ship and how.
- **MIT licence of the upstream base**: keep its notice; contributing back is planned.
- **EU AI Act**: an engineering assistant is unlikely to be high-risk, but a safety component would
  be. That is one more reason the boundary at the top of this document does not move.

| Engineering coverage | 45 % |
| Verification | 45 % |
| Commissioning | 15 % (the physical part is gated on purpose) |
| Lifecycle | 45 % |
| Governance and security | 55 % |

| Product law | 5 % |

What already sets it apart is the part most tools leave out: every write is planned, checked and
recorded; nothing is claimed that was not measured; and the model is held to a gate. What keeps it
from being a company product is mostly breadth (HMI, alarms, libraries, other languages, other TIA
versions), the second machine (installation, a second user, the teacher signing in from elsewhere),
and the processes a customer will audit (four eyes, IEC 62443, SBOM, support).
